# Stage 1A Complexity Inventory Through Task 5

**Status:** review-only inventory at Task-5 handoff commit `56cca80`; no production,
test, schema, or execution change is authorised by this document.

## Scope and decision language

This inventory covers mechanisms that exist after portable-state Tasks 1–5. It does not
inventory proposed Tasks 6, 6A, 7, or 8, Stage 2 work, or a future repair command. A dormant
Task-6 compatibility seam is included only because Task 2 already installed it.

The owning requirements are the approved Git-native architecture design (`Architecture`),
Tasks 1–5 of the portable-state implementation plan (`PS Task n`), the publication-review
hard gate (`Publication gate`), and the approved Task-5 fallback/recovery design (`Task-5
design`). The code and progress ledger were used to confirm that each mechanism landed.

`Surface` deliberately separates two things that the current specifications often bind
together:

- **Observable guarantee** is behaviour a human, agent, Git workflow, or recovery operator
  can rely on. Its implementation may still change.
- **Private mechanism** is one way Gateway currently proves or delivers a guarantee. It is
  not a compatibility promise merely because a plan or test names its exact shape.

The decisions below are Stage-1A recommendations, not authority to refactor. **Retain** keeps
the mechanism and its guarantee for the first alpha. **Replace** keeps the stated observable
guarantee but proposes a cheaper private mechanism. **Remove/defer** finds no Task-5 V1
guarantee that justifies carrying the mechanism now. The human gate must approve the actual
guarantee set and recovery posture before any change is executable.

The category column uses only the five required categories: `product requirement`,
`security boundary`, `crash consistency`, `compatibility`, and `speculative hardening`.
Likelihood is about the first local Git-native alpha, not an eventual multi-user Fabric
deployment.

## Inventory judgment

The dominant conclusion is not “remove safety.” The retained first-alpha contract should
still include Git as acceptance authority, deterministic tracked state, cross-workspace
isolation, untrusted-repository containment, no silent merge loss, attributable human/agent
actions, no overwrite of concurrent direct edits, durable prepared evidence, automatic
recovery of unambiguous old/new states, and byte-preserving block on ambiguity.

The disproportionate cost comes from proving those guarantees repeatedly through private
representations. The highest-value simplification candidates are therefore:

1. remove compatibility for unreleased SQLite/journal/proof formats;
2. remove raw SQLite storage-class, hostile-trigger, and hidden-metadata adversary checks
   from hot paths;
3. replace complete-record CAS with one workspace/lifecycle revision and aggregate loader;
4. replace global operation-history inventories and action-specific receipts with an
   explicit lifecycle owner plus a generic bounded idempotency ledger;
5. replace duplicate policy/review/prior-candidate proof envelopes with one versioned
   checkpoint manifest; and
6. retain the Linux crash and concurrent-edit guarantees while consolidating descriptor,
   mount, topology, rename, fsync, and recovery reasoning behind one filesystem transaction
   boundary.

These recommendations intentionally preserve observable behaviour wherever the current
first-alpha threat model justifies it. Any proposal to weaken automatic recovery, semantic
merge, publication review, or direct-edit preservation belongs in the separate guarantee-
reduction artifact and still requires the human go/no-go.
